# Gamma Map engine: options chain → MNQ wall levels + thin Tradovate renderer (v1)

Build-order steps 2–8 turn a distilled CBOE options snapshot into the four wall lines, the gamma-flip line and the TOTAL/0DTE regime that a thin Tradovate indicator draws on an MNQ chart. The pipeline is a clean single-schema flow — a source-abstraction layer normalizes CBOE-live and Kaggle-historical chains onto one `(root, expiry, type, strike)` key, an IV-surface engine recovers parity forwards and gamma-from-IV, a GEX engine selects one max-|GEX| strike per side plus the flip, and a mapping/levels writer maps strikes to MNQ price with a strict no-look-ahead guard. The corrections C1–C9 are faithfully encoded: root is part of contract identity (C7), the basis leg is mandatory and computed from a parity anchor (C2/C9), gamma is a swappable callable so NDX can use the surface (C8), and the indicator-only scope is respected (exactly 5 lines + regime, ingredients hidden). The proxy/true-GEX boundary is enforced end to end and the Kaggle path is always flagged.

Watch for: (1) **the gamma-flip line never renders on the committed QQQ v1 path** — feed gamma isn't repriced across the spot scan, so `NetGEX(S)` is sign-preserving and the solver always returns `flip_no_root` (confirmed). (2) **0DTE walls are empty on the only committed live snapshot** — its trading day (Fri 2026-09-04) precedes every listed expiry, so two of the four flagship walls never populate and no test asserts a populated 0DTE wall on real data (confirmed). (3) **Strength renders WEAK for every wall on real data** — no single strike reaches the 7% GlobalShare floor across a broad universe, so the low/med/high readout the user asked for is non-informative in v1 (confirmed). (4) A stale local `.pyc` in the workspace carried a 2× GEX-formula bug (`0.02` vs `0.01`); the tracked source is correct and all 70 tests pass from a clean checkout, but it explains why an initial run may show 2 failures (confirmed).

**Verdict**: NEEDS_CHANGES

## High-level view

The transport is a two-adapter source-abstraction feeding one `NormalizedChain`, with `oi_available` as the single switch that decides true-GEX vs volume-proxy. That switch is honored at every downstream boundary and the Kaggle (no-OI) path is correctly tagged `proxy` and `oi_absent_volume_proxy`, never presented as OI-GEX.

The GEX formula is correct in source (`s·Γ·OI·M·S²·0.01`) and the corrections are respected: gamma is injected as a callable so NDX can swap in the surface, 0DTE excludes AM-settled roots on their own expiry date, and the sign convention is an explicit swappable model. The one behavioral defect is the flip: on the QQQ v1 path the injected gamma source ignores the hypothetical spot, so the flip scan varies only S² and can never cross zero. The flip line is therefore structurally absent until the NDX/surface repricing lands.

The surface engine lands the three hardest corrections — parity forwards (C9), exact AM/PM clocks (C7), and gamma-from-IV (C8) — and is pinned by data-driven tests against the real fixture that would fail on a revert.

Mapping enforces the mandatory basis leg and computes the C9-corrected parity basis while recording the raw feed basis alongside. One subtlety: the QQQ-derived corrected basis on the fixture is −15.77 vs a +21.10 raw basis, a 37-point sign-flipping swing, because the QQQ parity anchor is converted to NDX space through the ~41× ratio and compounds QQQ's small parity disagreement. It's internally consistent with C9 but larger than the headline NDX-only figure and deserves a sanity bound.

The renderer is a faithful thin renderer with a shared machine-checkable spec, correct skip rules, and strict no-look-ahead replay selection. Scope discipline holds: ingredients are not leaked into the levels file.

### Transport abstraction and the true-GEX vs proxy switch

Two adapters resolve every origin difference into one `NormalizedChain`, and `oi_available` is the single gate the GEX engine consults. The CBOE path joins greeks to content-addressed OI on the full `(root, expiry, type, strike)` key — the exact C7 fix, since a subset key re-merges NDX/NDXP and mis-states GEX by $7.1B. The Kaggle path carries no OI column, so it sets `oi_available=False` and emits `oi_absent_volume_proxy`. The flag rides through the profile, the wall, and into the rendered regime `(proxy)` suffix, so a proxy chain cannot be silently promoted to OI-GEX at any boundary.

One caveat on the proxy output itself: `2021-01-04_qqq.json` places the Put Wall (315) *above* the Call Wall (314), both above spot (309.42) — the structural noise of volume-weighting without OI. It's flagged as a proxy, so not a correctness bug, but it reinforces that these historical levels are diagnostic only.

### GEX formula and the stale-bytecode trap (confirmed)

The source formula is correct: `gex = s * gamma * weight * multiplier * s2 * 0.01`, and every factor checks out by hand (a −$7.5B put and a 250-NQ-contract call both reproduce exactly). A clean checkout passes all 70 tests.

The trap: the workspace shipped a stale `src/gammamap/__pycache__/gex.cpython-311.pyc` whose `co_consts` contained `0.02` where the source has `0.01`, doubling every GEX value and failing the two arithmetic tests until the cache was deleted:

```
co_consts: (..., 0.0, 0.02, ...)   # stale .pyc
LOAD_CONST 6 (0.02)                # doubled the formula
```

The `.pyc` is gitignored so it does not affect the repository, and after `find . -name '*.pyc' -delete` the constant is `0.01` and the suite is green. Worth a cache-guard or note so a first run isn't misdiagnosed as a formula bug.

### Gamma flip is structurally absent on the QQQ v1 path (confirmed)

`solve_gamma_flip` is correct in isolation — it scans a dense spot grid, interpolates genuine sign changes, picks the root nearest the reference spot, flags multiple roots, and reads the actual sign each side rather than hardcoding it. The unit test drives it with a spot-varying gamma and finds the root.

The production path does not. `_build_flip` (and `build_kaggle_levels`) inject `feed_gamma_source`, whose closure ignores the hypothetical spot:

```python
def gamma_at(contract, S):   # feed gamma is per-contract; S enters only via S² (SS5).
    return gamma_source(contract, S)   # feed_gamma_source ignores S
```

So `NetGEX(S) = S² · Σ(sᵢ·γᵢ·OIᵢ·M·0.01)` with the bracket spot-independent. Since `S²>0` over the whole grid, the sign never changes and no root exists. Confirmed on the fixture: `flip=None, roots=[], flags=['flip_no_root']`, and the committed `230612Z_QQQ.json` shows `gamma_flip: {mnq_price: null, neutral: true}`. The flip line the user explicitly asked for cannot render on the only path v1 ships. The surface path fixes this (its `surface_gamma` reprices at S), so the honest framing is that the flip is an NDX/v2 feature; shipping it as a v1 line that is always neutral is misleading.

### 0DTE universe empty on the committed live snapshot (confirmed)

`select_0dte_universe` correctly keeps only contracts expiring on the trading day and excludes AM-settled roots on their own expiry date (C7) — verified by a targeted unit test that keeps NDXP and drops the AM NDX today-expiry. But `build_levels` derives the trading day from the snapshot's quote timestamp, which on the canonical fixture is Friday 2026-09-04, while the earliest listed expiry is 2026-09-08 (Friday's own 0DTE already expired; Monday is Labor Day). The 0DTE universe is therefore empty, both 0DTE walls are null, and `gex_no_contracts` is raised. On a genuine intraday capture the trading day would coincide with a listed expiry and the walls would populate — but as shipped, the flagship 0DTE walls have no working example, and no test asserts a populated 0DTE wall on real data.

### Strength renders WEAK for every wall on real data (confirmed)

The banding logic and the resolution-floor confidence downgrade are both unit-tested against all four bands. The practical problem is the denominator: `GlobalShare = strike |GEX| / total gross |GEX|` across the whole universe. On the fixture the dominant put wall carries 5.9% and the call wall 3.5% — both under the 7% MODERATE floor — so every Total wall shows WEAK. Across a broad multi-expiry chain no single strike will ever reach 7/15/25%, so the low/med/high distinction the user requested is effectively always WEAK in v1. The fields are marked `uncalibrated`, which is honest, but the readout carries no information until the denominator is re-scoped or the thresholds are lowered for the Phase-1 within-snapshot regime.

### Surface engine: parity forward, exact clocks, gamma-from-IV

The three hardest corrections all land, pinned by tests against the real fixture that would fail on a revert. Parity recovers `F ≈ 29,511` at R² ≈ 0.9998 on NDXP 260908, below `current_price` exactly as C9 measured, with a two-pass recentering so the near-money band tracks the forward rather than the untrusted feed spot. The AM/PM clocks are exact to the second and correctly make an AM-settled contract non-live intraday on its expiry date. Gamma-from-IV recovers >100 distinct values across the 142-strike near-money strip versus the feed's ~14 (the C8 fix). No-arb violations (negative variance, calendar total-variance non-monotonicity) are flagged rather than silently corrected — so a bad fit surfaces as a quality flag instead of a smooth-looking wrong wall.

### Mapping: mandatory basis, C9 parity anchor, and a magnitude to bound

The two legs are kept distinct and the basis leg is never optional — the +42 reference reproduces exactly and a dedicated test asserts that dropping it (the C2 error) misplaces the level. The C9-corrected parity basis is what the writer uses, with the contaminated raw feed basis recorded alongside for audit.

The magnitude on the fixture warrants a bound. The QQQ chain has no NDX-space parity forward, so `_index_anchor` converts the QQQ-dollar forward to NDX-equivalent via `F_qqq / (qqq_spot/ndx_spot)`. QQQ's parity forward sits ~+0.59 above `current_price` (C9), and dividing by the ~0.0243 ratio amplifies that into ~+15 NDX points above the NDX feed spot, yielding a corrected basis of −15.77 against a +21.10 raw basis — a 37-point, sign-flipping swing. This is consistent with C9's opposite-direction disagreements, but it compounds a small ETF-side error across the ratio and lands directly on every mapped wall. Build-spec §9.1 already calls for a basis outlier filter and a theoretical `F ≈ S·exp[(r−q)τ]` fallback; neither is implemented, so a bad QQQ parity fit would propagate silently into the MNQ prices. A sanity bound plus a flag when corrected and raw disagree beyond a threshold would close this.

### Renderer and replay no-look-ahead

The indicator is a genuine thin renderer: pure `buildRenderModel`/`selectLevelsForReplay` functions with the Tradovate API isolated behind an adapter, and a shared `render_spec.json` that a Python contract test asserts against so the JS and the test cannot drift. The skip rules omit a line at a null price or zero GEX rather than faking authority — which is why the fixture renders only 2 of 5 lines (the empty-0DTE and neutral-flip cases above). `selectLevelsForReplay` picks the latest `asof ≤ chartTime` and never a future file, and `build_levels` enforces no-look-ahead server-side by rejecting any source timestamp after `asof` (tested both directions). Scope discipline holds: OI/IV/greeks/MaxPain/full-chain are computed and then deliberately not written, asserted by an explicit top-level-keys test.

### Supporting changes

`.gitignore`, `requirements-dev.txt`, and the READMEs are scoped to this work; no unrelated changes are bundled into the diff, and the raw Kaggle payload is gitignored with only small per-date levels committed.
